1.4 Batasan Masalah
Pengembangan difokuskan murni pada sisi frontend Android. Fokus merancang antarmuka pengguna, pemrosesan berkas, dan integrasi sistem, tanpa melakukan modifikasi terhadap logika backend.
Perancangan, pemilihan algoritma, dan pelatihan model Machine Learning tidak termasuk dalam ruang lingkup penelitian ini. Model Machine Learning digunakan dalam bentuk pre-trained model (model siap pakai) berformat ONNX yang disediakan oleh tim Machine Learning.
Sistem melakukan proses pra-pemrosesan citra (Byte-to-Image Sampling) dan inferensi ML secara lokal di dalam perangkat (on-device inference) menggunakan library ONNX Runtime.
Aplikasi dikembangkan menggunakan bahasa Kotlin dan memanfaatkan REST API (Retrofit) hanya untuk keperluan sinkronisasi riwayat deteksi dengan server backend.
Pengujian difokuskan pada aspek fungsionalitas aplikasi Android (keberhasilan pra-pemrosesan berkas, eksekusi model lokal, dan performa aplikasi latar belakang), bukan menguji arsitektur model ML itu sendiri.


3.1.1 Android dan Arsitektur Pengembangan
Pengembangan aplikasi Android modern membutuhkan pendekatan arsitektur yang terstruktur untuk memastikan skalabilitas dan kemudahan pemeliharaan sistem. Dalam proyek ini, aplikasi MangoDefend dikembangkan secara penuh menggunakan bahasa pemrograman Kotlin, dengan penargetan kompilasi pada SDK 36 dan batas kompatibilitas minimum pada SDK 23 (Android 6.0 Marshmallow).
Pemilihan bahasa Kotlin sebagai basis pengembangan didasarkan pada perkembangannya yang pesat di ekosistem Android. Menurut penelitian yang dilakukan oleh Coppola dkk. [6], Kotlin telah mendominasi ekosistem Android dan terbukti memberikan dampak positif yang signifikan terhadap kemudahan pemeliharaan (maintainability) perangkat lunak. Selain itu, keandalan Kotlin dalam pengembangan perangkat lunak modern [19] serta tersedianya fitur-fitur yang meminimalisir kesalahan seperti null-safety, menjadi faktor utama yang mendorong banyak pengembang melakukan migrasi pengembangan aplikasi dari Java ke Kotlin [20].
Untuk memastikan aplikasi terstruktur dengan baik, sistem ini mengadopsi pola arsitektur Model-View-ViewModel (MVVM) yang dikombinasikan dengan prinsip Clean Architecture. Arsitektur ini membagi sistem ke dalam beberapa lapisan tanggung jawab yang jelas dan terisolasi, yaitu lapisan Data, UI, Service, ML, dan Dependency Injection (DI). Pengelolaan dependensi dalam proyek ini diimplementasikan menggunakan library Dagger Hilt guna mempermudah proses injeksi objek secara terpusat.
Sementara itu, pada sisi antarmuka pengguna (UI), pengembangan dilakukan memanfaatkan framework deklaratif Jetpack Compose yang dipadukan dengan standar desain Material 3. Pendekatan deklaratif ini memungkinkan aplikasi untuk menyajikan tampilan yang lebih dinamis dan responsif saat menampilkan informasi status sistem maupun hasil deteksi malware kepada pengguna.


3.1.2 Malware dan Ancaman Keamanan Android
Malware (perangkat lunak berbahaya) didefinisikan sebagai program atau kode yang dirancang secara spesifik untuk merusak, mencuri data, atau mengganggu fungsionalitas normal dari sistem komputasi dan perangkat pengguna [7]. Serangan malware pada perangkat seluler, khususnya Android, terus menjadi ancaman serius. Penyebaran malware ini umumnya terjadi melalui pengunduhan aplikasi dari sumber atau toko pihak ketiga yang tidak resmi, lampiran email, atau klik pada tautan iklan berbahaya, yang dapat mengakibatkan kebocoran informasi pribadi, penurunan performa perangkat, hingga pengambilalihan kontrol sistem secara ilegal [10].
Saat ini, metode deteksi antivirus konvensional yang mengandalkan pencocokan tanda tangan (signature-based) menjadi semakin usang dan kurang efektif dalam menangani malware varian terbaru. Hal ini disebabkan karena pengembang malware modern secara aktif menggunakan teknik obfuscation (penyamaran kode) dan polymorphism (perubahan wujud) untuk memanipulasi struktur berkas agar lolos dari sistem keamanan keamanan [8]. Penelitian lebih lanjut juga menunjukkan bahwa modifikasi struktur biner dan penyembunyian pola kode jahat menjadi taktik utama yang membuat malware Android sulit dideteksi oleh sistem tradisional [9].
Sebagai respons terhadap ancaman yang dinamis dan tersembunyi tersebut, sistem keamanan Android membutuhkan mekanisme perlindungan yang berjalan secara proaktif, bukan sekadar pemindaian manual. Dalam aplikasi MangoDefend, mitigasi ancaman ini diimplementasikan melalui fitur proteksi real-time yang berjalan di latar belakang menggunakan Android Foreground Service (dengan tipe dataSync).
Aplikasi tidak melakukan polling sistem yang memboroskan baterai, melainkan mengawasi direktori rentan secara pasif (seperti Download atau folder aplikasi perpesanan) memanfaatkan kelas FileObserver yang mendengarkan kejadian (event) tingkat sistem operasi seperti CLOSE_WRITE (berkas selesai diunduh/ditulis) dan MOVED_TO (berkas dipindahkan). Dengan mekanisme pemantauan background ini, malware dengan teknik obfuscation sekalipun dapat segera ditangkap dan dianalisis seketika saat masuk ke perangkat pengguna.


3.1.3 Integrasi Machine Learning pada Android
Metode deteksi malware modern telah mengadopsi pendekatan machine learning (ML) untuk mempelajari pola statis dan dinamis dari berkas berbahaya. Berbagai penelitian mengevaluasi bahwa algoritma ML mampu mendeteksi malware Android dengan tingkat akurasi yang tinggi [11], [12]. Namun, sebagian besar pemrosesan antivirus masih bergantung pada komputasi server (cloud-based). Sebagai solusi yang lebih responsif, aplikasi MangoDefend mengimplementasikan on-device inference, yaitu menjalankan model ML secara langsung di dalam perangkat pengguna tanpa bergantung pada koneksi internet.
Dalam ruang lingkup penelitian ini, model machine learning tidak dikembangkan dari awal, melainkan menggunakan pre-trained model (model siap pakai) yang telah dilatih secara terpisah. Fokus pengembangan pada sisi frontend Android adalah bagaimana mengintegrasikan dan mengeksekusi model tersebut di lingkungan mobile.
Integrasi ini diwujudkan dengan memanfaatkan pustaka ONNX Runtime untuk Android (ai.onnxruntime:1.19.0). Berkas model ML (image_model_fixed.onnx) ditanamkan ke dalam folder assets pada proyek aplikasi. Tugas utama sistem frontend adalah memastikan berkas model disalin secara otomatis ke memori cache internal saat aplikasi dijalankan, untuk kemudian dimuat ke dalam memori eksekusi OrtSession. Selanjutnya, aplikasi bertugas menerima skor keluaran tensor dari model, memprosesnya dengan perhitungan matematis Softmax, dan menerjemahkannya ke dalam status antarmuka yang dapat dipahami pengguna, yaitu: Safe (< 40%), Suspicious (40% - 80%), atau Dangerous (>= 80%).

3.1.4 Pra-pemrosesan Representasi Citra Berkas
Salah satu pendekatan mutakhir dalam klasifikasi malware adalah mengubah berkas biner menjadi representasi citra dua dimensi, sehingga pola byte dapat divisualisasikan [17], [18]. Untuk dapat diolah oleh model Machine Learning yang disediakan, berkas yang ada di dalam penyimpanan perangkat Android tidak bisa langsung dimasukkan secara mentah, melainkan harus melalui tahap pra-pemrosesan (preprocessing) agar sesuai dengan format matriks yang dikenali oleh model.
Pada aplikasi MangoDefend, tugas krusial ini ditangani oleh sistem Android melalui kelas BinaryImagePreprocessor yang dikembangkan dengan Kotlin. Peran aplikasi dalam tahap ini adalah melakukan transformasi data secara efisien di dalam perangkat (on-device). Apabila pengguna memindai berkas biner seperti APK atau EXE, aplikasi akan melakukan metode Byte-to-Image Sampling dengan menghitung interval lompatan (step size) sebesar panjang_berkas / 50176. Operasi Input/Output (I/O) pada Android akan membaca berkas tersebut dan mengambil tepat 50.176 sampel byte secara berkala dari penyimpanan lokal.
Setelah sampel byte diekstraksi, tugas aplikasi selanjutnya adalah melakukan normalisasi data (byte 0-255 diubah ke float 0.0-1.0) dan menyusunnya menjadi struktur tensor multidimensi [1, 3, 224, 224] (Batch size=1, Channels=3, Height=224, Width=224). Struktur tensor hasil olahan sistem frontend inilah yang kemudian diumpankan ke model ONNX untuk dilakukan klasifikasi. Melalui pendekatan ini, batas tanggung jawab aplikasi Android menjadi jelas, yakni sebagai penyedia data pra-pemrosesan dan pengeksekusi model

3.1.5 Komunikasi Backend dan Penyimpanan Lokal
Pada pengembangan aplikasi seluler modern, mekanisme komunikasi data dengan sistem pusat (backend) memerlukan integrasi antarmuka pemrograman aplikasi (API) yang andal. Dalam sistem ini, pertukaran data antara aplikasi Android dan server dikelola menggunakan pustaka Retrofit dan OkHttp. Pustaka ini memfasilitasi pengiriman data seperti nilai hash dan riwayat deteksi melalui protokol REST API yang dieksekusi secara asinkron di latar belakang, sehingga tidak mengganggu responsivitas antarmuka aplikasi.
Selain komunikasi jaringan, sistem juga membutuhkan mekanisme penyimpanan lokal untuk menyimpan hasil analisis secara offline. Untuk memenuhi kebutuhan tersebut, arsitektur data dikelola menggunakan Room Database, yang menyediakan lapisan abstraksi pada SQLite. Penggunaan Room memungkinkan pengelolaan basis data menjadi lebih terstruktur dan aman, serta mempercepat proses pemuatan data riwayat pemindaian saat aplikasi dijalankan.


3.2.1 Gambar Sistem Saat Ini
Saat ini, sistem deteksi malware yang dikembangkan masih terbatas pada implementasi berbasis situs web. Kondisi ini mengharuskan interaksi dilakukan melalui peramban (browser) dan tidak dapat dijalankan secara mandiri langsung pada perangkat pengguna. Di sisi lain, model machine learning yang berperan sebagai komponen utama dalam proses analisis malware juga masih berada pada tahap pengembangan dan evaluasi untuk memastikan tingkat akurasi serta konsistensi performanya.
Keterbatasan ini menyebabkan sistem belum sepenuhnya optimal untuk digunakan secara praktis, terutama oleh pengguna umum yang membutuhkan aplikasi deteksi malware yang cepat dan mudah diakses. Melihat celah tersebut, diperlukan pengembangan lebih lanjut agar sistem antivirus dapat diimplementasikan dalam bentuk aplikasi seluler, khususnya pada perangkat Android yang memiliki jumlah pengguna sangat tinggi. Dengan ketersediaan aplikasi berbasis seluler, proses deteksi dapat dieksekusi secara langsung di dalam perangkat tanpa harus bergantung pada akses situs web, sehingga pengalaman pengguna menjadi jauh lebih efisien, responsif, dan intuitif.
3.2.2 Pengembangan Sistem
Menindaklanjuti keterbatasan pada implementasi antivirus berbasis machine learning sebelumnya, pengembangan sistem diarahkan agar fungsionalitas tersebut dapat digunakan di berbagai macam perangkat, khususnya pada perangkat bersistem operasi Android.
Dalam pengembangannya, Kotlin dipilih sebagai bahasa dan framework utama untuk membangun aplikasi antivirus pada ekosistem Android ini. Kotlin digunakan karena karakteristik sintaks kodenya yang ringkas, tingkat keamanan yang tinggi, serta dukungan penuh dari ekosistem Android, sehingga sangat memudahkan proses implementasi maupun pembaruan aplikasi secara berkelanjutan.
Untuk memastikan pengembangan berjalan terstruktur, aplikasi Android ini dibangun dengan menerapkan pola arsitektur Model-View-ViewModel (MVVM) yang dipadukan dengan prinsip Clean Architecture. Antarmuka pengguna dirancang secara deklaratif menggunakan framework Jetpack Compose. Sementara itu, untuk mengatasi masalah performa saat melakukan pemindaian berkas biner dalam jumlah besar, tugas-tugas berat dialihkan ke latar belakang menggunakan komponen Jetpack WorkManager untuk pemindaian penuh, dan Foreground Service untuk pemantauan perlindungan secara real-time. Integrasi machine learning pada perangkat (on-device inference) diwujudkan dengan memanfaatkan library ONNX Runtime untuk Android, yang memungkinkan model untuk memproses representasi citra secara lokal tanpa harus membebani server.

Berdasarkan rancangan perangkat lunak, sistem menyediakan beberapa fungsionalitas utama yang dapat diakses oleh pengguna maupun dipicu oleh sistem operasi:
